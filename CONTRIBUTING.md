# Contributing

Thanks for wanting to add a project. Keep it simple — open a Pull Request editing `README.md` (and `600-open-source-projects-notion.csv` if you can).

## Criteria

A project must be:

1. **Open-source** — with a recognized OSI license (MIT, Apache-2.0, AGPL, GPL, BSD, etc.).
2. **Actively maintained** — a commit within the last 6 months, or a clear "stable" status from the maintainers.
3. **Useful to a general audience** — not a niche fork, demo repo, tutorial project, or thin wrapper.
4. **Fits an existing category** — Developer Tools, Data / Analytics, Design / Frontend, AI / ML, DevOps / Infrastructure, Productivity / Collaboration, Business / Commerce, Self-hosted / Personal, Security / Auth, or Maps / Geo. Don't invent a new category without opening an issue first.

## Format

Add the project at the end of the most relevant category table. Use this format:

```
| <next #> | [Project Name](https://github.com/owner/repo) | One-line description. |
```

- Keep descriptions under ~80 characters.
- Lead with the function, not marketing language ("Open-source X alternative" beats "The best way to X").
- Use the project's official GitHub URL — not a mirror or fork.

If you can, add the same row to `600-open-source-projects-notion.csv` so the spreadsheet stays in sync.

## Process

1. Fork the repo.
2. Edit `README.md` (and the CSV if possible).
3. Open a PR with a short justification — a link to the project and one sentence on why it fits.
4. One project per PR (makes review easier).

Removals (unmaintained projects, broken links, license changes) are welcome too — same flow.

## Not accepted

- Closed-source or "source-available" projects.
- Projects with no commits in over a year and no clear stable status.
- Personal forks or demo repos.
- Paid SaaS tools with an "open-source SDK" but no self-hostable core.
